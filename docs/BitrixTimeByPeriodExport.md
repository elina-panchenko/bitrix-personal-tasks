# BitrixTimeByPeriodExport.gs — учёт времени за период

Отдельный файл к основному скрипту личных задач (`BitrixTasksToSheets.gs`).
Добавляет пункт меню **«Учёт времени за период»**, который выгружает весь ваш
учёт времени за произвольный срок — по одной строке на каждую запись учёта.

## Что делает

- Спрашивает срок **одной строкой** в формате `дд.мм.гггг-дд.мм.гггг`
  (например `07.07.2026-15.07.2026`).
- Тянет все ваши записи учёта времени за этот срок через
  `task.elapseditem.getlist` (фильтр `USER_ID` = вы, `CREATED_DATE` в диапазоне).
- Оставляет записи по задачам, где вы исполнитель (`RESPONSIBLE_ID` = вы).
- Пишет лист **`Учёт времени за период`**: по строке на запись плюс заголовок
  с итогом (сколько записей, задач и суммарное время).

### Колонки листа

| Колонка | Что в ней |
|---|---|
| Дата и время | Когда сделана запись учёта (`CREATED_DATE`) |
| Длительность | `Ч:ММ:СС` |
| Длительность, мин | То же в минутах (для суммирования/сводных) |
| Комментарий | Текст записи (HTML вычищен) |
| Задача | Название задачи |
| ID задачи | Числовой ID |
| Проект/Группа | Название рабочей группы задачи |
| Ссылка | Прямая ссылка на задачу в портале |

## Подключение

1. Откройте тот же проект Apps Script, где лежит `BitrixTasksToSheets.gs`
   (**Расширения → Apps Script**).
2. Создайте новый файл и вставьте туда `BitrixTimeByPeriodExport.gs` целиком.
3. В `onOpen` основного скрипта добавьте строку с кнопкой:
   ```js
   .addItem('Учёт времени за период', 'tpExportTimeByPeriod')
   ```
   (в этом репозитории она уже добавлена в `BitrixTasksToSheets.gs`).
4. Сохраните, обновите вкладку таблицы — в меню **«Bitrix»** появится
   **«Учёт времени за период»**.

Вебхук общий с основным скриптом (свойство `BITRIX_WEBHOOK`) — повторно вводить
не нужно.

## Настройки (вверху файла)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TP_DEST_SHEET` | `Учёт времени за период` | Имя листа результата |
| `TP_RESPONSIBLE_ID` | `''` | Пусто — владелец вебхука; иначе конкретный Bitrix ID строкой |
| `TP_ONLY_MY_TASKS` | `true` | `true` — только задачи, где вы исполнитель; `false` — все задачи, где вы вели время |
| `TP_PERIOD` | `''` | Для запуска из редактора (без диалога): срок в формате `дд.мм.гггг-дд.мм.гггг` |
| `TP_TIMEZONE` | `''` | Пусто — пояс скрипта; иначе, напр., `Europe/Moscow` |
| `TP_MAX_ELAPSED` | `5000` | Предохранитель: максимум записей учёта (защита от лимита 6 минут) |

## Запуск из редактора (без меню)

Впишите срок в `TP_PERIOD` (например `07.07.2026-15.07.2026`) и запустите
функцию `tpExportTimeByPeriod`. Результат и сообщения — в журнале
(**Просмотр → Журналы**).

## Как отделён от основного скрипта

Файл самостоятельный: все функции и переменные имеют префикс `tp`, поэтому не
конфликтуют с основным скриптом в одном проекте Apps Script. Собственного
`onOpen` в файле нет — пункт меню добавляется в `onOpen` основного скрипта одной
строкой (см. «Подключение»).

## Методы Bitrix REST

| Метод | Зачем |
|---|---|
| `task.elapseditem.getlist` | Записи учёта времени за срок (постранично, `NAV_PARAMS`) |
| `tasks.task.get` | Название/группа/исполнитель задачи (с кэшем) |
| `sonet_group.get` | Название рабочей группы (с кэшем) |
| `user.current` | Запасной способ определить ваш ID, если его нет в URL вебхука |

## Отладка

- **«Вебхук не задан»** — сохраните вебхук в основном скрипте: меню «Bitrix» →
  «Указать вебхук».
- **«Неверный формат периода»** — срок нужно вводить как `дд.мм.гггг-дд.мм.гггг`,
  одной строкой, например `07.07.2026-15.07.2026`.
- **Пустой лист** — за этот срок нет ваших записей учёта времени, либо все они
  на задачах, где вы не исполнитель (тогда поставьте `TP_ONLY_MY_TASKS = false`).
