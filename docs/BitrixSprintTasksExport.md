# BitrixSprintTasksExport.gs — как работает скрипт

Подробное описание Google Apps Script [`BitrixSprintTasksExport.gs`](../BitrixSprintTasksExport.gs):
что он делает, как настраивается, какие функции внутри и какие методы Bitrix24 REST вызывает.

---

## 1. Что делает скрипт

Скрипт живёт внутри Google-таблицы (Расширения → Apps Script) и добавляет в неё меню
**«Спринт»** с двумя действиями:

| Пункт меню | Функция | Что выгружает | На какой лист |
|---|---|---|---|
| **Выгрузить задачи спринта** | `seExportSprintTasks` | **ВСЕ** задачи **одного** названного спринта Bitrix24 (Scrum) — не только ваши | `Задачи спринта` |
| **Выгрузить мои отложенные задачи** | `seExportDeferredTasks` | Все задачи, где **вы исполнитель** и статус = «Отложена» | `Отложенные` |
| **Выгрузить задачи за период** | `seExportTimeByPeriod` | Детализацию по **учёту времени**: по строке на каждую запись учёта, где **вы** учитывали время за указанный период | `Учёт времени` |
| **Указать вебхук** | `seSetWebhook` | — (сохраняет URL входящего вебхука портала) | — |

По каждой задаче в таблицу попадают: название, статус, приоритет, постановщик,
исполнитель, даты (создания / крайний срок / завершения), **план и факт времени** в
часах, **отклонение** факта от плана, признак **«в срок?»**, **стори-поинты** (SP,
только для спринта), проект/группа и **прямая ссылка** на задачу в Bitrix.

Лист каждый раз **полностью перезаписывается** (`sheet.clear()`), поэтому выгрузка —
это всегда «свежий снимок», а не дозапись.

### Чем отличается от соседних скриптов

- `BitrixTasksToSheets.gs` — тянет **ВАШИ** задачи по **всем** спринтам.
- `BitrixSprintTasksExport.gs` (этот) — тянет **ВСЕ** задачи **ОДНОГО** названного спринта.
- Все скрипты в одном проекте Apps Script переиспользуют один и тот же сохранённый
  вебхук (общий ключ свойств `BITRIX_WEBHOOK`), так что настраивать его нужно один раз.

## 2. Как подключить (один раз)

1. Откройте таблицу → **Расширения → Apps Script**. Вставьте файл целиком.
2. Сохраните, обновите вкладку таблицы — появится меню **«Спринт»**.
3. **Вебхук.** Если в этом же проекте Apps Script вы уже пользовались
   `BitrixTasksToSheets.gs` / `BitrixCreateSprints.gs`, вебхук уже сохранён — шаг можно
   пропустить. Иначе: меню **«Спринт» → «Указать вебхук»** и вставьте входящий вебхук
   портала.
   - В Bitrix: **Разработчикам → Другое → Входящий вебхук**, с правом **`task`**.
   - URL вида `https://ВАШ-ПОРТАЛ.bitrix24.ru/rest/123/xxxxxxxxxx/`.
4. Меню **«Спринт» → «Выгрузить задачи спринта»**.

### Запуск из редактора (без меню)

Выберите функцию `seExportSprintTasks` и нажмите **«Выполнить»**. Результат и все
сообщения уйдут в журнал (**Просмотр → Журналы**). Диалоги (`ui.prompt`/`ui.alert`) при
таком запуске недоступны, поэтому вебхук должен быть уже сохранён.

## 3. Настройки (переменные вверху файла)

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `SE_SPRINT_NAME` | `'Спринт июль 2'` | Имя спринта ровно как в Битриксе. Регистр и лишние пробелы **не важны** (нормализуется). |
| `SE_GROUP_ID` | `''` | ID Scrum-группы строкой. Пусто — искать спринт во всех доступных группах. Заданное значение ускоряет поиск и снимает неоднозначность при одноимённых спринтах в разных группах. |
| `SE_DEST_SHEET` | `'Задачи спринта'` | Лист для результата (создаётся сам, перезаписывается). |
| `SE_PAGE_SIZE` | `50` | Bitrix отдаёт задачи страницами по 50 (справочно). |
| `SE_MAX_TASKS` | `2000` | Предохранитель от бесконечного цикла и лимита выполнения 6 минут. |
| `SE_DEFERRED_SHEET` | `'Отложенные'` | Лист для отложенных задач (перезаписывается). |
| `SE_DEFERRED_STATUS` | `6` | Код статуса Bitrix «Отложена». |
| `SE_TIMELOG_SHEET` | `'Учёт времени'` | Лист для детализации по учёту времени за период (перезаписывается). |
| `SE_PERIOD_FROM` | `''` | Начало периода `ГГГГ-ММ-ДД` — только для **запуска из редактора** (в таблице период спрашивается диалогом). |
| `SE_PERIOD_TO` | `''` | Конец периода `ГГГГ-ММ-ДД` — тоже только для запуска из редактора. |
| `SE_PROP_WEBHOOK` | `'BITRIX_WEBHOOK'` | Ключ в свойствах скрипта, где хранится URL вебхука (общий с соседними скриптами). |
| `SE_PROP_GROUP_ID` | `'BITRIX_SCRUM_GROUP_ID'` | Ключ в свойствах скрипта с сохранённым ID Scrum-группы. |

`SE_TASK_FIELDS` — список полей задачи, которые запрашиваются у Bitrix
(`ID, TITLE, STATUS, PRIORITY, CREATED_BY, RESPONSIBLE_ID, CREATED_DATE, DEADLINE,
CLOSED_DATE, TIME_ESTIMATE, TIME_SPENT_IN_LOGS, GROUP_ID`).

`SE_HEADERS`, `SE_DEFERRED_HEADERS` и `SE_TIMELOG_HEADERS` — заголовки колонок листов
(порядок = порядок столбцов).

## 4. Колонки результата

### Лист «Задачи спринта» (`SE_HEADERS`)

`ID` · `Название` · `Статус` · `Приоритет` · `Постановщик` · `Исполнитель` ·
`Создана` · `Крайний срок` · `Завершена` · `План, ч` · `Факт, ч` · `Откл., ч` ·
`В срок?` · `SP` · `Проект/Группа` · `Ссылка`

Сверху листа — две строки-шапки:
- **строка 1**: имя спринта, группа, даты `начало—конец`, статус спринта;
- **строка 2**: сводка «Задач: N (завершено K), SP всего: X».

### Лист «Отложенные» (`SE_DEFERRED_HEADERS`)

То же самое, **без колонки `SP`** (стори-поинты для отложенных не нужны). Сверху —
одна строка-шапка с ID исполнителя и общим числом задач.

### Лист «Учёт времени» (`SE_TIMELOG_HEADERS`)

Здесь **одна строка = одна запись учёта времени** (а не задача), поэтому одна и та же
задача может встречаться несколько раз.

`Дата и время` · `Длительность` · `Длительность, мин` · `Комментарий` · `Задача` ·
`ID задачи` · `Проект/Группа` · `ID спринта` · `Спринт` · `Ссылка`

- **`Дата и время`** — когда сделана запись учёта (`CREATED_DATE`), формат `гггг-мм-дд чч:мм`.
- **`Длительность`** — текст `Ч:ММ:СС` (например `0:20:02`).
- **`Длительность, мин`** — то же время в минутах **числом** с округлением до 0.1
  (`20`, `11.8`, `0.1`). Записывается именно числом — в русской локали Google Sheets
  покажет его с запятой (`11,8`) и по нему можно считать суммы.
- **`Комментарий`** — комментарий к записи учёта (`COMMENT_TEXT`), может быть пустым.
- **`Задача`** / **`ID задачи`** — название и ID задачи, к которой относится запись.
- **`Проект/Группа`** — название рабочей группы задачи.
- **`ID спринта`** / **`Спринт`** — заполняются, **только если задача входит в спринт**;
  иначе обе ячейки пустые.
- **`Ссылка`** — прямая ссылка на задачу в Bitrix.

Сверху — одна строка-шапка: период, ID пользователя, число записей и **итоговая
длительность** за период.

## 5. Как устроена работа: поток данных

### Выгрузка спринта — `seExportSprintTasks()`

```
SE_SPRINT_NAME
     │
     ▼
seFindSprint_()  ──► находит спринт по имени, возвращает его id и groupId
     │                 (через seCandidateGroups_ + seSprintsOfGroup_)
     ▼
seFetchGroupTasks_(groupId)  ──► все задачи группы (постранично, tasks.task.list)
     │
     ▼
для каждой задачи: tasks.api.scrum.task.get
     │   ├─ scrum.entityId  — в каком спринте задача (фильтр: == sprintId)
     │   └─ scrum.storyPoints — стори-поинты
     ▼
строки таблицы (со справочниками имён и форматированием времени/дат)
     │
     ▼
запись на лист SE_DEST_SHEET (перезапись, шапка, сводка, автоширина)
```

Ключевой момент: `tasks.task.list` **не отдаёт** привязку задачи к спринту и
стори-поинты, поэтому по **каждой** задаче группы делается отдельный запрос
`tasks.api.scrum.task.get`. Задачи, у которых `entityId` не совпал с id нужного
спринта, отбрасываются. Отсюда — предохранители `SE_MAX_TASKS` и кэши имён.

### Выгрузка отложенных — `seExportDeferredTasks()`

```
seResponsibleId_()  ──► ваш ID (владелец вебхука из URL, запасной путь — user.current)
     │
     ▼
seFetchTasks_({ RESPONSIBLE_ID: id, STATUS: 6 })  ──► задачи «Отложена», где вы исполнитель
     │
     ▼
строки таблицы  ──►  запись на лист SE_DEFERRED_SHEET
```

Здесь достаточно одного `tasks.task.list` с фильтром — обращаться к Scrum-методам не
нужно.

### Выгрузка за период — `seExportTimeByPeriod()`

```
sePromptPeriod_()  ──► период { from, to } (диалог или SE_PERIOD_FROM/SE_PERIOD_TO)
     │
     ▼
seFetchElapsed_(userId, from, to)  ──► записи учёта времени (task.elapseditem.getlist,
     │                                  фильтр по CREATED_DATE и USER_ID, постранично)
     ▼
для каждой записи:
     │   seTaskInfo_(taskId)      — название/группа/спринт задачи (tasks.task.get +
     │                              tasks.api.scrum.task.get), с кэшем по задаче
     │   seSprintNameById_(...)   — имя спринта по его id (из списка спринтов группы)
     ▼
строки таблицы (дата, Ч:ММ:СС, минуты числом, комментарий, задача, проект, спринт, ссылка)
     │
     ▼
запись на лист SE_TIMELOG_SHEET (перезапись, шапка с итоговой длительностью, автоширина)
```

Записи учёта берутся методом `task.elapseditem.getlist` — по фильтру `USER_ID` (вы) и
диапазону `CREATED_DATE`. У записи есть только `TASK_ID`, поэтому название задачи,
проект и спринт подтягиваются отдельно и **кэшируются по задаче** (одна и та же задача
в нескольких записях не дёргает API повторно). Спринт определяется так же, как в
выгрузке спринта: `entityId` из `tasks.api.scrum.task.get` сверяется со списком спринтов
группы; если это не спринт (например, бэклог) — колонки спринта остаются пустыми.

> **Про «завершённые за период».** Выгрузка построена на записях **учёта времени** — в
> ней окажется всё, где вы списывали время в этот период. Отдельного отбора «задачи,
> которые я завершила за период» здесь нет (в таблице нет колонки статуса/даты
> завершения). Если такой отбор тоже нужен — это отдельная небольшая доработка.

## 6. Функции скрипта

### Меню и UI

| Функция | Назначение |
|---|---|
| `onOpen()` | Триггер Google Sheets: при открытии таблицы строит меню «Спринт». Обёрнут в `try/catch` — если UI недоступен (запуск не из таблицы), тихо выходит. |
| `seUi_()` | Безопасно возвращает объект UI или `null` (чтобы код работал и без диалогов, из редактора). |

### Вебхук

| Функция | Назначение |
|---|---|
| `seSetWebhook()` | Показывает диалог ввода URL вебхука, проверяет формат регуляркой `^https:\/\/.+\/rest\/\d+\/.+`, добивает `/` в конце и сохраняет в свойства скрипта под ключом `BITRIX_WEBHOOK`. При запуске из редактора (нет UI) бросает понятную ошибку. |
| `seGetWebhook_()` | Читает сохранённый вебхук из свойств скрипта. Если не задан — бросает ошибку с инструкцией. |
| `seWebhookOwnerId_()` | Достаёт ID пользователя-владельца вебхука — число между `/rest/` и следующим `/` в URL. Используется как «ваш» ID для фильтров и ссылок. |

### Вызов Bitrix REST

| Функция | Назначение |
|---|---|
| `seCallBitrix_(method, params)` | Единая точка вызова REST: `POST` на `<вебхук><method>.json` с JSON-телом. Разбирает ответ, кидает осмысленную ошибку, если пришёл не-JSON, если в теле есть `error`, или если HTTP-код ≥ 400. Возвращает распарсенный объект `data`. |

### Главное действие — спринт

| Функция | Назначение |
|---|---|
| `seExportSprintTasks()` | Оркестратор выгрузки спринта: находит спринт → тянет задачи группы → фильтрует по `entityId` спринта, попутно считая стори-поинты и завершённые → пишет лист с шапкой, сводкой, автошириной колонок и «замороженной» строкой заголовков. В конце пишет в журнал и показывает `toast`. |

### Поиск спринта

| Функция | Назначение |
|---|---|
| `seFindSprint_(wantedName)` | Перебирает группы-кандидаты и их спринты; сравнивает нормализованные имена. Возвращает `{ sprint, groupId }`. Если не нашёл — бросает ошибку **со списком реально найденных спринтов** (удобно для отладки опечаток в имени). |
| `seCandidateGroups_()` | Возвращает список групп, где искать спринт. Если задан `SE_GROUP_ID` (или сохранённый `BITRIX_SCRUM_GROUP_ID`) — только он. Иначе определяет Scrum-группы автоматически: постранично собирает `GROUP_ID` из задач владельца вебхука. |
| `seSprintsOfGroup_(groupId)` | Список спринтов одной группы через `tasks.api.scrum.sprint.list`. Нормализует форму ответа (массив либо `{ sprints: [...] }`). При ошибке/недоступности возвращает `[]` (группа не Scrum). |

### Отложенные задачи

| Функция | Назначение |
|---|---|
| `seExportDeferredTasks()` | Выгрузка ваших задач со статусом «Отложена» на лист «Отложенные»: один `tasks.task.list` с фильтром, затем запись листа с шапкой. |
| `seResponsibleId_()` | Ваш ID: сначала владелец вебхука (`seWebhookOwnerId_`), запасной путь — `user.current`. |

### Задачи за период (учёт времени)

| Функция | Назначение |
|---|---|
| `seExportTimeByPeriod()` | Оркестратор выгрузки за период: спрашивает период → тянет записи учёта времени → по каждой подтягивает задачу/группу/спринт (с кэшем) → пишет лист «Учёт времени» с итоговой длительностью в шапке. Считает суммарное время за период. |
| `sePromptPeriod_(ui)` | Спрашивает начало и конец периода двумя диалогами (из редактора — берёт `SE_PERIOD_FROM`/`SE_PERIOD_TO`). Проверяет формат `ГГГГ-ММ-ДД`, при необходимости меняет даты местами. Возвращает `{ from, to, fromApi, toApi }` (границы дня `00:00:00`…`23:59:59`) или `null`, если отменили. |
| `seFetchElapsed_(userId, fromApi, toApi)` | Постранично тянет `task.elapseditem.getlist` по фильтру `USER_ID` + диапазон `CREATED_DATE`. Устойчив к разной форме ответа; ограничен `SE_MAX_TASKS`. |
| `seTaskInfo_(taskId, cache)` | По ID задачи возвращает `{ title, groupId, responsibleId, sprintId }` (через `tasks.task.get` и `tasks.api.scrum.task.get`), с кэшированием по задаче. При ошибке доступа оставляет ID вместо названия. |
| `seSprintNameById_(sprintId, groupId, cache)` | Название спринта по его id. Разворачивает список спринтов группы (`seSprintsOfGroup_`) один раз и кэширует; если id — не спринт (бэклог), возвращает пустые `{ id:'', name:'' }`. |

### Получение задач (постранично)

| Функция | Назначение |
|---|---|
| `seFetchGroupTasks_(groupId)` | Тонкая обёртка: `seFetchTasks_({ GROUP_ID: groupId })`. |
| `seFetchTasks_(filter)` | Постранично тянет `tasks.task.list` по произвольному фильтру, с полями `SE_TASK_FIELDS`, сортировкой по дате создания. Идёт по страницам через поле `next`, пока оно есть и приходят задачи; останавливается по `SE_MAX_TASKS`. |

### Вспомогательное для листа

| Функция | Назначение |
|---|---|
| `sePadRows_(rows)` | Выравнивает все строки по ширине заголовка (добивает пустыми ячейками), чтобы `setValues` не падал на строках разной длины (например, на строке-заглушке «нет задач»). |

### Справочники и форматирование

| Функция | Назначение |
|---|---|
| `seNorm_(s)` | Нормализация строки для сравнения имён: `trim` + нижний регистр + схлопывание пробелов. |
| `seStatusName_(s)` | Код статуса → название: `1` Новая, `2` Ждёт выполнения, `3` Выполняется, `4` Ждёт контроля, `5` Завершена, `6` Отложена, `7` Отклонена. |
| `sePriorityName_(p)` | Код приоритета → название: `0` Низкий, `1` Обычный, `2` Высокий. |
| `seSprintStatus_(s)` | Статус спринта → русское название: `planned` → запланирован, `active` → активный, `completed` → завершён. |
| `seUserName_(id, cache)` | ID пользователя → «Имя Фамилия» через `user.get`, с кэшированием в переданный объект (чтобы не дёргать API повторно). При ошибке возвращает сам ID. |
| `seGroupName_(id, cache)` | ID группы → её название через `sonet_group.get`, с кэшированием. |
| `seTaskUrl_(portalBase, responsibleId, taskId)` | Собирает прямую ссылку на задачу: `<портал>/company/personal/user/<исполнитель>/tasks/task/view/<id>/`. |
| `seHours_(sec)` | Секунды → часы, округление до 0.1; пусто, если данных нет или ноль. |
| `seRound1_(x)` | Округление до одного знака после запятой. |
| `seDuration_(sec)` | Секунды → строка `Ч:ММ:СС` (например `0:20:02`) для колонки «Длительность». |
| `sePad2_(x)` | Двузначное дополнение нулём (минуты/секунды) для `seDuration_`. |
| `sePick_(obj, keys)` | Первое непустое значение по списку ключей — Bitrix отдаёт поля то `ВЕРХНИМ_РЕГИСТРОМ` (учёт времени), то `camelCase` (задачи). |
| `seOnTime_(t)` | Логика «В срок?»: для завершённых сравнивает дату закрытия с крайним сроком (`в срок` / `просрочена` / `без срока`); для незавершённых — `просрочена (не завершена)` если срок в прошлом, иначе `в работе`. |
| `seFmtDate_(s)` | Дата-время → строка `yyyy-MM-dd HH:mm` в часовом поясе скрипта. |
| `seFmtDay_(s)` | Дата → строка `dd.MM` (для шапки спринта). |

## 8. Частые вопросы и отладка

- **«Спринт … не найден».** Проверьте `SE_SPRINT_NAME` (регистр не важен, но текст —
  да). В ошибке скрипт печатает список реально найденных спринтов — сверьте написание.
  Если спринтов вообще нет — вебхук не видит нужную Scrum-группу; задайте `SE_GROUP_ID`.
- **«Не удалось определить Scrum-группу автоматически».** У владельца вебхука нет задач,
  по которым можно вычислить группу. Впишите ID группы в `SE_GROUP_ID`.
- **Пустой лист / «в спринте нет задач».** Задачи есть, но недоступны вебхуку, либо ни у
  одной `entityId` не совпал с id спринта (задача не привязана к спринту в Scrum).
- **Долго выполняется / упирается в 6 минут.** Основная стоимость — по одному
  `tasks.api.scrum.task.get` на каждую задачу группы. Ограничьте область поиска через
  `SE_GROUP_ID` и держите `SE_MAX_TASKS` разумным.
- **Вместо имени — числовой ID.** Справочный вызов `user.get`/`sonet_group.get` не прошёл
  (права/доступ) — это не критично для выгрузки.
- **Время «пустое».** В Bitrix у задачи не заполнены `TIME_ESTIMATE` /
  `TIME_SPENT_IN_LOGS` — план/факт просто нечего показывать.
- **«Учёт времени»: пусто за период.** За выбранные даты у вас нет записей учёта
  (`task.elapseditem`), либо период задан наоборот — проверьте формат `ГГГГ-ММ-ДД`
  (даты, введённые местами, скрипт сам поменяет). Границы включают весь день:
  `00:00:00` начала … `23:59:59` конца.
- **«Учёт времени»: колонки спринта пустые.** Значит задача не входит в спринт (лежит в
  бэклоге или это обычная задача) — так и задумано.
- **«Учёт времени»: минуты показаны с точкой, а не запятой.** Значение записывается
  числом; разделитель зависит от локали таблицы (**Файл → Настройки → региональные
  настройки** → русская локаль покажет `11,8`).
