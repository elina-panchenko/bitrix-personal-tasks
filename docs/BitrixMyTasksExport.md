# BitrixMyTasksExport.gs — все мои задачи (без спринтов)

Отдельный файл к основному скрипту личных задач (`BitrixTasksToSheets.gs`).
Добавляет пункт меню **«Все мои задачи (без спринтов)»**, который выгружает все
задачи, где вы — исполнитель, вне зависимости от спринтов.

## Что делает

- Тянет через `tasks.task.list` все задачи с фильтром `RESPONSIBLE_ID` = вы
  (постранично, по 50).
- Спринты не учитываются вообще: скрипт не вызывает ни один метод
  `tasks.api.scrum.*`, поэтому в выборку попадают задачи из скрам-групп,
  из обычных проектов и задачи без проекта — одинаково.
- Пишет лист **`Мои задачи`** (перезаписывается при каждом запуске). В первой
  строке — сводка: всего задач / в работе / завершено / просрочено.

### Колонки листа

| Колонка | Что в ней |
|---|---|
| ID | Числовой ID задачи |
| Название | Название задачи |
| Статус | Новая / Ждёт выполнения / Выполняется / Ждёт контроля / Завершена / Отложена / Отклонена |
| Приоритет | Низкий / Обычный / Высокий |
| Постановщик | Кто поставил задачу |
| Исполнитель | Вы (для контроля) |
| Создана / Крайний срок / Завершена | Даты (`yyyy-MM-dd HH:mm`) |
| План, ч | Оценка времени (`TIME_ESTIMATE`), часы |
| Факт, ч | Затрачено по учёту времени (`TIME_SPENT_IN_LOGS`), часы |
| Откл., ч | Факт минус план |
| В срок? | в срок / просрочена / просрочена (не завершена) / в работе / без срока |
| Проект/Группа | Название рабочей группы задачи (пусто, если задача без проекта) |
| Ссылка | Прямая ссылка на задачу в портале |

## Подключение

1. Откройте тот же проект Apps Script, где лежит `BitrixTasksToSheets.gs`
   (**Расширения → Apps Script**).
2. Создайте новый файл и вставьте туда `BitrixMyTasksExport.gs` целиком.
3. В `onOpen` основного скрипта добавьте строку с кнопкой:
   ```js
   .addItem('Все мои задачи (без спринтов)', 'mtExportMyTasks')
   ```
   (в этом репозитории она уже добавлена в `BitrixTasksToSheets.gs`).
4. Сохраните, обновите вкладку таблицы — в меню **«Bitrix»** появится
   **«Все мои задачи (без спринтов)»**.

Вебхук общий с основным скриптом (свойство `BITRIX_WEBHOOK`) — повторно вводить
не нужно.

## Настройки (вверху файла)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MT_DEST_SHEET` | `Мои задачи` | Имя листа результата |
| `MT_RESPONSIBLE_ID` | `''` | Пусто — владелец вебхука; иначе конкретный Bitrix ID строкой |
| `MT_INCLUDE_CLOSED` | `true` | `false` — только активные задачи (без статуса «Завершена») |
| `MT_MAX_TASKS` | `5000` | Предохранитель: максимум задач (защита от лимита 6 минут) |

## Запуск из редактора (без меню)

Выберите функцию `mtExportMyTasks` и нажмите «Выполнить». Результат и
сообщения — в журнале (**Просмотр → Журналы**).

## Как отделён от основного скрипта

Файл самостоятельный: все функции и переменные имеют префикс `mt`, поэтому не
конфликтуют с основным скриптом и с `BitrixTimeByPeriodExport.gs` в одном
проекте Apps Script. Собственного `onOpen` в файле нет — пункт меню добавляется
в `onOpen` основного скрипта одной строкой (см. «Подключение»).

## Чем отличается от «Обновить задачи + ретро» в основном скрипте

Основная кнопка тоже выгружает все ваши задачи, но дополнительно ходит в скрам
(спринты, стори-поинты, ретро) — это десятки-сотни лишних REST-вызовов.
`mtExportMyTasks` — лёгкая выгрузка «только задачи»: быстрее, не трогает
листы «Спринты»/«Ретро»/«Планирование» и работает, даже если скрам на портале
не настроен.

## Методы Bitrix REST

| Метод | Зачем |
|---|---|
| `tasks.task.list` | Все задачи с фильтром `RESPONSIBLE_ID` (постранично) |
| `user.get` | Имя постановщика/исполнителя (с кэшем) |
| `sonet_group.get` | Название рабочей группы (с кэшем) |
| `user.current` | Запасной способ определить ваш ID, если его нет в URL вебхука |

## Отладка

- **«Вебхук не задан»** — сохраните вебхук в основном скрипте: меню «Bitrix» →
  «Указать вебхук».
- **Пустой лист** — у этого пользователя нет задач, где он исполнитель;
  проверьте `MT_RESPONSIBLE_ID` (пусто = владелец вебхука, его ID — число
  после `/rest/` в URL вебхука).
- **Выгрузилось ровно 5000** — сработал предохранитель `MT_MAX_TASKS`;
  увеличьте его или выключите `MT_INCLUDE_CLOSED`, чтобы отсечь старые
  завершённые задачи.
